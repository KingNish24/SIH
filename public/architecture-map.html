Flow A • Public / Employer Journey (No Login)

How an Employer Checks a Candidate's Degree

  1. 1. Quick Check on Home (/): Enter 12-digit APAAR ID (e.g. 412398471029) in Hero card → POST /api/verify returns inline summary + link to full receipt.
  2. 2. Full Verification (/verifier): Checks 3 things at once:
    • Was student admitted within AICTE seat limit? (admissions table)
    • Is the degree Ed25519 signature valid and not revoked? (degrees table)
    • Did the student grant DPDP privacy consent or provide a VIDYA-DPDP-* pass?
  3. 3. Scanned Marksheet & Offline QR Check (/verifier):
    • Upload a marksheet image → Browser OCR/VLM compares printed CGPA against DB CGPA (`8.94` vs tampered `9.80`).
    • Paste or scan QR JSON → Verifies Ed25519 signature offline using GET /api/keys public key.
Flow B • Student Privacy & Consent Pass Journey

How a Student Controls Who Sees Their Marks

  1. 1. Sign In (/login?redirect=/student): Highlights Student card (`student.rahul`) → sets HttpOnly session cookie → redirects to /student.
  2. 2. Global Consent Toggle (POST /api/student/consent):
    • If REVOKED: Public checks on /verifier mask the student's name (`R**** S*****`), DOB, email, and phone.
    • If GRANTED: Public checks show full verified particulars.
  3. 3. One-Time Access Pass (POST /api/student/token):
    • Student creates a scoped pass (e.g. VIDYA-DPDP-8492-A19F) for a specific employer.
    • Student clicks "Test This Pass in Public Verifier →" which opens /verifier?apaar=...&token=VIDYA-DPDP-..., validates the pass, and marks single-use passes as CONSUMED.

2. Working Backend Architecture: Layer-by-Layer Request Flow

How Astro 6 SSR, Middleware, Core Libraries, and Cloudflare D1 / WebCrypto process every request.

LAYER 1 • EDGE ENTRY & ROUTING src/middleware.ts + src/pages/[lang]/*
Middleware Pipeline (`src/middleware.ts`)
  • 1. Language Resolution: Detects /[lang]/... prefix (22 Eighth Schedule languages) or gov_preferred_lang cookie → sets Astro.locals.lang.
  • 2. Session Authentication: Reads sih_session HttpOnly cookie → calls getSessionUser(db, token) in src/lib/auth.ts → populates Astro.locals.user.
  • 3. RBAC Route Protection: Checks ROUTE_ROLE_MAP (/institution → `INSTITUTE_ADMIN`, /aicte → `AICTE_ADMIN`, /university → `UNIVERSITY_ADMIN`, /student → `STUDENT`). Redirects unauthorized users to /${lang}/login?redirect=....
  • 4. Security Headers: Appends CSP, `X-Frame-Options: DENY`, `X-Content-Type-Options: nosniff`, `Referrer-Policy`.
LAYER 2 • SSR PAGES & REST API ROUTES src/pages/*.astro & src/pages/api/**/*.ts
Server-Side Rendered Views & JSON Endpoints
SSR Pages (`src/pages/`):
index.astro, login.astro, institution.astro, aicte.astro, university.astro, student.astro, verifier.astro + [lang]/* mirrors
API Endpoints (`src/pages/api/`):
auth/login, auth/logout, institution/roster, aicte/anomalies, university/degree, student/consent, student/token, student/passkey, verify, verify/merkle, keys
LAYER 3 • DOMAIN & CRYPTOGRAPHY SERVICES src/lib/*.ts
Core Business Logic & WebCrypto Engine
  • • src/lib/attestation.ts: Core verification engine (`verifyCredential`), Ed25519 key generation/signing (`getSigningKeys`), SHA-256 Merkle root builder, and Yes/No predicate proof signer.
  • • src/lib/auth.ts: PBKDF2-HMAC-SHA256 (100,000 iterations) password verifier & session manager.
  • • src/lib/qr.ts: Zero-dependency SVG QR code matrix generator for W3C Verifiable Credentials.
  • • src/lib/i18n.ts + src/locales/*.json: 23-language dictionary loader (343 keys per language).
LAYER 4 • PERSISTENCE & STORAGE ADAPTER src/lib/db.ts + db/schema.sql
Dual-Mode Database Adapter (`getDB(Astro.locals)`)

In Cloudflare production, binds directly to Cloudflare D1 (`env.DB`) and Cloudflare KV (`env.KV`). In local `astro dev`, automatically falls back to MemoryDBAdapter seeded with the exact same relational tables and rows.
